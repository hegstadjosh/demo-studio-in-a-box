# Interface direction from the source production

This file holds the interface direction the person gave during the source production, generalized only enough to remove the product. Each rule records that person's judgment as a hypothesis for a new film and gives what to do, why it mattered and how to check a still.

## Structure and containers

- **Put every piece of text in a container, without going blocky.** Loose text and borderless panels looked amorphous; the same words in a table, card or box read as a product. Heavy rectangles read as a crude patch, so keep borders thin and light. Check: no label, number or line of copy sits on bare background, and the screen resembles a professional website, not a wireframe.
- **Group what the viewer compares.** Two scores belong in one container split by a divider, the numbers boxed and set apart from the names, so the comparison reads at a glance. Check: compared figures share one container and names never crowd the numbers.
- **Show each widget once, and only when the moment needs it.** A duplicated scoreboard or a redundant indicator splits attention. Check: list every widget in the still; none appears twice.
- **Build hierarchy and depth.** Equal-weight elements looked amateur; weight, size and shadow tell the viewer where to look first. Check: in a half-second glance, the most important element is obvious.
- **Give every string a job.** Text repeating the picture, a cryptic tagline or an unneeded label only costs reading time. Check: for each string, say what it tells the viewer that the picture does not.

## Components and brand

- **Build from real components, not hand-drawn imitations.** Shapes drawn to resemble controls looked improvised; the accepted redesign used an established component library themed with the product's tokens, plus the product's own components, such as its profile circles. Check: every control in the still exists in that library or in the product.
- **Match the product's fonts, colours, wordmark and navigation.** One wrong font or text colour makes the film look like another product. Check: set the still beside a screenshot of the live product.
- **Keep accent colours few, each with one meaning.** Extra accents made screens noisy; a colour marking both a person and a penalty confuses both. Check: count the accents and name each one's meaning.
- **Give one kind of event one pop-up form.** Pop-ups of one type entering differently looked like bugs. Each carries a short, conventional type label and no explanation. Check: line up the pop-up stills; within a type, shape and position match, and a newcomer would know each label.

## Scale, density and legibility in a moving frame

- **Never wrap or truncate by accident.** A label on two lines or a clipped name reads as broken. Check: no ellipses and no unplanned second lines; shorten or shrink until each fits.
- **Hold one scale across screens.** Zoomed-in screens looked cartoonish, and one screen suddenly zoomed out broke continuity. Check: text and component sizes match across adjacent stills.
- **Let dense screens work at a glance.** The viewer needs one readable example and the sense that there are many, not every tile. Check: one tile is legible and the quantity is obvious.
- **Keep captions out of the interface.** Narration captions belong in the overlay style viewers know from short-form video, not inside product panels, where they read as product copy. Check: each caption sits in the caption layer, consistently placed and clear of names and the wordmark, which stays in one corner throughout.
- **Animate pop-ups like game rewards.** Floating, fading, decelerating entries draw the eye; straight slides look mechanical. A still cannot show this; play the cut.

## Portrait and mobile

- **Redesign for the phone instead of enlarging.** Widening the frame around a desktop layout is not a mobile interface; a phone needs a phone layout, such as a feed showing one item at a time with natural scrolling. Check: the still looks like an app a person would use on a phone.

## When the real product cannot be shown

- **Build the screens, but make each read as an ordinary page of the product.** The person rejected captured live screens and wanted built ones done well; a familiar page tells viewers where to go. Check: a user of the product would recognise the page and its standard details, such as buttons.
- **Depict only what exists.** A feature not yet live, or a pop-up implying a score the product never gives, makes a false claim. Check every visible feature against the truth list.
- **Give non-product material no product interface.** Outtakes ran as plain full-screen video with a title, because product chrome would present them as product. Check: no product chrome outside product scenes.
